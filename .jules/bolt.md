## 2025-02-18 - Optimize Order Financial Batch Planning Routines and ZIP Helpers

**Learning:** In order financial batch planning (`unie_cortex/services/order_financial_planning.py`), `supplier_anchor_postal_from_engagement` was calling `_postal5_from_origin_entry` inside a row loop over `rows` for every order line, repeatedly re-parsing SKU origin postals $O(N_{\text{rows}})$ times instead of pre-parsing once per SKU $O(N_{\text{skus}})$. Furthermore, `destinations_from_order_rows_weighted_zip5` was appending destination ZIPs unit-by-unit inside a loop over quantities into a list before feeding `Counter`, causing $O(\text{quantity})$ memory allocations. Pre-computing SKU origin postals and replacing list allocations with a direct `defaultdict(int)` accumulator, along with fast-path string checks for 5-digit ZIPs in `_zip3` and `_norm_postal_5`, reduced 10,000-row batch planning execution time from 115.73ms to 45.18ms (~2.56x speedup).

**Action:** When aggregating or weighting rows by catalog metadata (like SKUs) or quantity units, always pre-index SKU metadata before row iterations and aggregate directly into a dictionary instead of building intermediate unit-by-unit lists.
