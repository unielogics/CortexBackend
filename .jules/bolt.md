## 2025-02-14 - Optimized Geographic Distance Calculation and Caching
**Learning:** For static or small domain lookups (such as the 1000 unique US ZIP3 prefix possibilities), a combination of module-level coordinate pre-computation in radians and outer-function caching using `@functools.lru_cache` yields massive gains. Furthermore, by inlining distance calculations and comparing the raw sinusoidal component $h$ rather than converting to real-world kilometers (avoiding `math.asin` and multiplication), we bypass expensive CPU floating point operations entirely on the cold-miss path. Decorating the outer function with `@lru_cache` instead of inner helpers is ~3.4x faster for cache hits because it allows string-cleaning operations and input normalization to be completely bypassed.
**Action:** When mapping structured variables (e.g. ZIPs, states, airports) against a fixed target grid or coordinates table, always pre-compute radians at the module scope, inline a minimized haversine comparison (avoiding `math.asin`), and wrap the entry function with `@functools.lru_cache(maxsize=1024)`.
