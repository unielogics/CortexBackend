## 2026-03-03 - Caching Geographic Distance Checks for Fixed Static Hubs
**Learning:** Geographic distance calculations (e.g. haversine formula) performed on a static set of hubs (like the 48 contiguous U.S. states) are extremely CPU-intensive when repeated in hot loops. Because the input cardinality is low (only 1,000 possible 3-digit ZIP prefixes in the U.S.), memoization via `functools.lru_cache` guarantees a 100% hit rate after initial cold lookups, shifting lookup complexity from expensive floating-point trigonometric calculations to O(1) dictionary lookups. Additionally, pre-converting static hub latitude and longitude coordinates to radians at the module level completely eliminates math function overhead on cache misses.
**Action:** Always identify functions that operate on finite input domains (like ZIP codes, states, carrier codes, or preset configurations) and apply `lru_cache` and module-level pre-calculations to bypass heavy mathematical calculations or list scans.
